GOAD Blue Team Program

// instrument, detect, harden, validate — on a deliberately broken AD forest

GOAD (Game of Active Directory) is an intentionally vulnerable Active Directory range from Orange Cyberdefense: five Windows servers, three domains, two forests, and a catalogue of real-world misconfigurations. Most people use it to practise attacks. This page tracks the opposite: everything I plan and do to see each attack, stop it, and prove both with evidence.

Ground rules

  • The range lives on its own VLAN with no route to anything real. Attacks never leave it.
  • Stock GOAD build, no custom weaknesses, so every result maps back to the public write-ups.
  • A detection counts as validated only after the attack was run and the alert fired, with the time-to-detect recorded.
  • A path counts as hardened only after the control is applied and the same attack is re-run and fails.
  • Rules, configs and the BloodHound inventory stay in the private homelab repo. This page carries results and method only.
02 — The plan

Seven phases, each with an exit test

Checked boxes are done. The matrix and the log below are the proof.

PHASE 0next

Build the range

Deploy stock GOAD with the Proxmox provider (Packer templates, Terraform, Ansible) into a dedicated lab VLAN.

  • Choose provider and lab layout (Proxmox · GOAD full)
  • Provisioning VM with the GOAD toolchain
  • Lab VLAN with no route to the home LAN; management access only over the mesh VPN
  • Snapshot every VM as the clean baseline
  • Calendar the 180-day Windows evaluation licence rebuild
exit: all five hosts resolve, both forests authenticate, goad check passes.
PHASE 1planned

Instrument

Get the right telemetry off every host before touching a single detection.

  • Wazuh agent on all five hosts (GOAD's Wazuh extension or my existing manager)
  • Sysmon with a community config (process, network, named pipes, registry)
  • Advanced audit policy: Kerberos ticket ops, DS access, account management, object access
  • SACLs on tier-0 objects so 4662 and 5136 actually fire
  • PowerShell script-block logging, SYSVOL file integrity monitoring
exit: every telemetry source named in the matrix is arriving in Wazuh from every host.
PHASE 2planned

Baseline

Know the "known bad" before changing it.

  • SharpHound collection from a domain user, graph in BloodHound
  • Record every misconfiguration the GOAD docs list and where it lives
  • Export the alert volume per host for a quiet day (the noise floor)
exit: graph and inventory committed to the private repo; noise floor documented.
PHASE 3planned

Detect

One detection per attack path, each mapped to MITRE ATT&CK and tuned against the noise floor.

  • Author Wazuh rules (or adopt and tune community rules) per matrix row
  • Severity, ATT&CK tag, and a short "what to do" field on every rule
  • Alerts routed to the same Discord channel the rest of the homelab uses
exit: every matrix row has a rule ID; status moves to building.
PHASE 4planned

Attack to validate

Purple-team each path using the public GOAD write-ups, from the attacker box, one at a time.

  • Run the technique; capture the exact command and timestamp
  • Confirm the alert fired; record time-to-detect and any gaps
  • Fix false negatives and re-run until it fires reliably
exit: matrix row flips to validated; event logged with ATT&CK ID.
PHASE 5planned

Harden and re-test

Apply the control the matrix prescribes, then re-run the same attack.

  • Apply the fix (policy, ACL, template, service setting)
  • Re-run the attack: it must fail, and the attempt must still alert
  • Re-collect BloodHound and diff the graph against the baseline
exit: matrix row flips to hardened; before/after recorded.
PHASE 6planned

Respond

A runbook per validated detection, exercised at least once.

  • Contain, scope, and recover steps per alert (credential reset, ticket and certificate revocation, host isolation)
  • Tabletop one full chain end to end, from spray to domain admin
  • Measure time-to-contain the way time-to-detect was measured
exit: runbook linked from every validated row in the matrix.
